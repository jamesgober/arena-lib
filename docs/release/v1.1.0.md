# Release v1.1.0 - Bump soundness and generation retirement

**Date:** 2026-11-12
**Compare:** [`v1.0.0...v1.1.0`](https://github.com/jamesgober/arena-lib/compare/v1.0.0...v1.1.0)

## Summary

This release fixes two defects found in an independent review and adds a few fallible entry points. Every change is additive; no 1.0 item changed shape.

## Fixed

- **`Bump` was undefined behaviour on every allocation.** It derived the pointer it wrote through from a shared `&[u8]` borrow of the chunk, which Miri rejects under both Stacked Borrows and Tree Borrows. Chunks are now raw allocations from the global allocator, held as `NonNull<u8>` and freed on drop, and every returned pointer is produced with `add` on the chunk pointer. No slice reference over a chunk is created while allocations are live. `cargo miri test` is clean under both models, and CI now runs it on every push.
- **Stale `Index` handles could resolve again after 2^32 reuses of a slot.** The 32-bit generation counter wrapped. A slot whose counter is exhausted is now retired: it leaves the free list for good, and lookups with any handle issued for it return `None`. A retired slot keeps its storage until the arena is dropped. In a tight loop the wrap took about 11 seconds in release builds.
- **`Bump::try_alloc` aborted on allocation failure** instead of returning `Error::CapacityExceeded`. Chunk allocation is now checked, and an impossible size or an allocator failure returns the error.

## Added

- `Arena::try_get`, `Arena::try_get_mut` and `Arena::try_remove`, which return `Error::StaleIndex` for a handle that does not refer to a live element. Before this release no function returned `StaleIndex`.
- `Bump::try_with_capacity`, the fallible form of `Bump::with_capacity`.
- A Miri CI job (Stacked Borrows and Tree Borrows).

## Changed

- New `Bump` chunks double in size from the starting size, up to 1 MiB per chunk (or the starting size, if larger), so a large arena holds O(log n) chunks instead of one per 4 KiB.
- Zero-sized `Bump` allocations no longer allocate a chunk, including over-aligned zero-sized types.
- `Arena::clear` skips retired slots when it rebuilds the free list. The free list still hands out the lowest slot first.
- Documentation: `Error::StaleIndex`, `CapacityExceeded` and `CounterOverflow` describe when each is returned, and the arena docs state that an `Index` is not tied to the arena that issued it.

## Compatibility

- **MSRV:** Rust `1.85` (unchanged).
- **Edition:** `2024`.
- **Runtime dependency:** `hashbrown 0.15` (unchanged).
- `Bump` remains `Send` and not `Sync`.

## Verified

- `cargo fmt --all -- --check`, stable and 1.85.
- `cargo clippy --all-targets -- -D warnings` with default, all and no default features, stable and 1.85.
- `cargo test --all-features`, stable and 1.85.
- `cargo test --release --test generation_wrap -- --ignored` (the full 2^32-cycle check).
- `cargo +nightly miri test`, Stacked Borrows and Tree Borrows.
- `cargo doc --no-deps` with `RUSTDOCFLAGS=-D warnings`, default and all features.
- `cargo package` and `cargo semver-checks` against 1.0.0.
